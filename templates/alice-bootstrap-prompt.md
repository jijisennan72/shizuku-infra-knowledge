# 🚀 新チャット用プロンプトテンプレート

別プロジェクトでアリスとのチャットを始めるとき、冒頭に貼るテンプレート。

---

## テンプレート A: 汎用版（しずくネット配下の新プロジェクト）

```
このプロジェクトは「しずくネット」配下のサービスです。
インフラ（さくらVPS + Coolify + Traefik + Supabase OSS）は他プロジェクトと共通。

共通ナレッジは以下のGitHub非公開リポジトリにあります：
https://github.com/jijisennan72/shizuku-infra-knowledge

インフラ絡みのトラブルが出たら、以下の順で確認してください：
1. README.md で全体像を把握
2. incidents/ で過去の類似事例を検索
3. runbooks/ で標準手順を確認

特に以下の3原則は絶対ルールとして守ってください：
- 🔴 パッケージ更新・VPS再起動の前は必ず相談
- 🔴 Dockerネットワーク間通信はIPではなくコンテナ名で参照
- 🔴 UFW FORWARDルールはサブネット全体許可
```

---

## テンプレート B: 障害対応モード

既に障害が発生していて、急いで対応してほしい時：

```
【緊急】しずくネット配下のサービスで障害発生中。

障害の症状: [ここに症状を書く]
対象サービス: [サービス名]
最近の変更: [直前にした作業があれば]

まず以下を参照して、過去の類似事例がないか確認してください：
https://github.com/jijisennan72/shizuku-infra-knowledge/tree/main/incidents

類似事例が見つかれば、その復旧手順を応用してください。
見つからなければ、runbooks/docker-network-diagnostics.md の診断フローに沿って進めてください。
```

---

## テンプレート C: 予防保守モード

定期点検や、再起動前のチェック時：

```
しずくネットVPSの予防保守を行いたい。

以下のチェックリストを参照して、現在の状態を点検してください：
https://github.com/jijisennan72/shizuku-infra-knowledge/blob/main/runbooks/vps-reboot-checklist.md

各項目について、実行コマンドとその結果を踏まえて、問題があれば報告してください。
```

---

## 💡 使い方のコツ

1. **URLは必ず書く** — Claudeは自動でweb_fetchできるが、URLがないと過去ナレッジを参照できない
2. **目的を明確に** — 「診断したい」「予防保守したい」「新規構築したい」で読むべきドキュメントが違う
3. **既知の情報は最初に伝える** — アリスが推測で動くより、ジージが知ってる事実を先に共有する方が早い
